# 午间零售价的逐时效用参数调整

本轮希望在原利润目标下，让午间零售价自然降低一些。只更新24对二次效用系数 `hourly_utility.a/b`；相对[上一轮逐时效用实验](hourly-utility.md)，代码、训练超参、17维状态结构、储能、新能源、负荷和批发价输入均保持不变。没有新增价格跟随规则、目标动作、奖励项或调度约束。

本轮已完成500回合训练和唯一1回合最终测试。h10–14均价下降约2.473%，但购电峰值和小时变化增大，因此应标记为**最新降价候选，不是全面改善的最终方案**。参数、真实单次结果与图表见[本轮实验记录](../../experiments/sac_midday_price_500_20261018/README.md)，上一轮逐时系数配置及结果继续保留。

## 上一轮午间价格为何偏高

原利润同时取决于零售差价与响应后的售电量。提高价格虽然扩大单位差价，也会改变需求，因此利润最优价由批发价、效用参数、类别负荷以及原三次满意度/参与率迭代共同决定。不存在“午间必须低价”的规则，也不能只看TOU就判断某个价格是否最优。

上一轮需要区分两种情况：h9–12的静态利润最优价已低于上限，保存的SAC价格却接近32.5，存在策略相对静态目标的偏差；h13–15的静态最优本来就在32.5上限，此时贴边具有经济激励。前者不能仅归因于响应参数，有限训练、函数近似和SAC熵目标都可能贡献偏离。

| 小时 | 上一轮保存的SAC零售价 | 上一轮静态最优价 | 本轮参数的静态最优价 |
|---|---:|---:|---:|
| h9 | 32.4269 | 31.185 | 30.960 |
| h10 | 32.4578 | 31.700 | 31.250 |
| h11 | 32.4657 | 32.100 | 31.515 |
| h12 | 32.4708 | 32.365 | 31.610 |
| h13 | 32.4779 | 32.500 | 31.920 |
| h14 | 32.4773 | 32.500 | 31.890 |
| h15 | 32.4789 | 32.500 | 31.725 |

这些静态值来自 `checks/sac_midday_price/parameter_proposal.json`：按原响应与利润公式，在26.5–32.5、步长0.005的1201点网格上逐小时计算，没有加载Actor。它们是无储能的离线价格诊断，不能替代SAC学习结果或联合调度评价；不作为训练标签、动作输入或执行规则。

## 本轮24对系数的构造

配置为 [`configs/sac/midday_price_500.json`](../../configs/sac/midday_price_500.json)。效用仍写作 `U_h(L)=a_h*L²+b_h*L`，其中 `a_h<0`；曲率 `kappa_h=-a_h`，响应参考价 `reference_h=b_h+2*a_h*B_h`。三类用户继续按原份额使用 `a_hi=a_h/share_hi`、`b_hi=b_h`。

以先前 `hourly_utility_500.json` 的系数为起点，将h9–15的名义曲率和参考价设为 `kappa=0.000825`、`reference=30.5`，两侧用以下权重过渡：

| 小时 | 权重w |
|---|---:|
| h0–6 | 0 |
| h7 | 0.25 |
| h8 | 0.75 |
| h9–15 | 1 |
| h16 | 0.75 |
| h17 | 0.25 |
| h18–23 | 0 |

```text
kappa_new = (1-w)*kappa_old + w*0.000825
reference_new = (1-w)*reference_old + w*30.5
a_new = -kappa_new
b_new = reference_new + 2*kappa_new*nominal_baseline_load
```

权重对应两侧三小时的升余弦过渡：h6/7/8/9为0/0.25/0.75/1，h15/16/17/18为1/0.75/0.25/0。零权重小时直接保留上一轮配置中的a、b数值；没有对最终动作或负荷进行平滑。核心时段的a相同，但b随基线负荷变化，完整24对参数保存在配置中。

这是a、b的联动调整，不能描述为每小时参考价都下降：原参考价高于30.5的小时向下调整，低于30.5的小时向上调整。原TOU账单参照、批发价以及26.5–32.5零售价边界均未改变。运行时参考价仍按当前三类float32负荷之和计算，名义表与运行时的小量浮点差异遵循已有实现。

较小的kappa会增加理性需求的价格敏感性，不能称为简单“减弱弹性”。参考价和价格相对位置也必须一起考虑：当零售价低于有效参考价时，原公式允许增加用电；当前响应没有跨时补回机制。a、b属于人工建模调参，没有通过真实客户数据拟合。

## 离线诊断能说明什么

在预先定义的午间价格窗口h10–14，静态最优均价由32.233降至31.637，下降约0.596澳分/kWh。候选静态最优价下，h11–15的削减率约为8.53%、9.58%、12.23%、12.00%、10.62%。这些数值说明新参数提供了较低午间价格的利润激励，不保证训练500回合后策略一定学到这些价格。

如果策略仍沿用上一轮较高价格，新参数下h11、h12的静态削减率约为17.32%、17.76%，会高于上一轮实际的11.84%、10.77%。因此需要同时检查价格是否下降和需求响应是否合适，不能只凭静态最优曲线宣布改进。给定价格网格内，候选h9–15的最大削减约18.33%；这是原公式的数值结果，没有增加18.33%的响应限制。

需求变化还会改变购电量、储能调度空间及利润。即使午间价格下降，也不能预先宣称购电峰值或全日波动下降。本轮不修改训练超参来同时追逐学习偏差；若最终策略仍偏离静态目标，应记录该偏差，不能继续把它全部归因于效用参数。

## 参数固定记录与实验流程

`checks/sac_midday_price/selection_before_training.json` 记录参数方案于2026-10-18 07:24:08 UTC固定，并保存配置SHA256、权重和构造式。完整的 `parameter_proposal.json` 报告在训练启动后整理完成，其文件完成时间不能充当训练前选参的证据；训练前固定方案的依据是前述selection记录。文档核对时确认：

- selection中的配置SHA256与当前配置文件相符。
- proposal中的24个a和24个b与当前配置逐值一致，运行目录保存的配置也一致。
- 与上一轮配置相比，仅 `hourly_utility` 字段改变；两轮冻结源码manifest的哈希映射相同。

协议保持seed 42、固定同一个24小时日，负荷与批发价使用原名义曲线，风电功率固定，曲率、需求和参与三项环境噪声均为0。SAC训练探索和回放抽样仍有随机性。

每轮训练500回合，即12000环境步；`evaluation_every=0`，没有训练前、中途或训练结束时的内部策略评价。训练完成后只对最终检查点执行一次 `evaluate --cases 1`。价格窗口预先定义为h10–14；响应窗口为h11–15，削减率按原始负荷加权计算。随后只读取已保存的单次测试轨迹做前后比较，不平均多个场景、不平滑测试动作或负荷。

实际完成记录为500回合、12000环境步、92168次梯度更新和1个24小时最终测试回合。核心源码哈希与上一轮相同，没有新增算法代码。本轮进行了参数一致性、冻结源码和已保存轨迹的物理核验，未重新运行92项单元测试；92项测试通过及CI绿色状态属于上一轮相同代码版本的验证记录，不能表述为本轮新跑了92项测试。

平均降价目标在这一次测试中实现了，但学习误差与局部响应问题仍存在。例如h11实价31.2366低于静态近似最优31.515，h12实价32.1618高于静态近似最优31.610。即使窗口均价接近离线诊断的31.637，也不能认为逐小时已经最优。

h12出现了价格下降、削减率反而上升的情况。这两轮效用参数不同：该小时名义响应参考价由约31.1281降至30.5，曲率由约0.0009010降至0.000825；实际价格高于参考价的差距因此由约1.3427增至1.6618。原响应公式在这组参数下产生更强削减，不能把单独降价与减小削减等同起来。

本轮最大的购电变化出现在h2→h3，而上一轮在h15→h16。虽然h0–6的效用系数保留原值，重新训练的共享网络仍可改变这些小时的策略；仅在午间修改参数不保证其他小时动作保持原样。SOC、功率界和购电平衡等轨迹核验通过，物理可行也不代表购电形状更好。

因此，本轮适合作为降低午间均价的候选记录，不能称为全日更平滑或全面改善。利润下降约0.266%，购电峰值、峰谷差和波动指标上升，需要与降价目标一起权衡。效用环境已经改变，前后利润差也不能解释为同一环境下算法提升。单位沿用澳分/kWh、kW、kWh的建模约定；固定日的一次测试不构成对未知日泛化的证据。
